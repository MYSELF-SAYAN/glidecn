**GlideCN** is an open-source page transition engine designed for Next.js App Router and React. It delivers <TransitionCount /> hardware-accelerated 3D shaders, portals, origami folds, and fluid masks with copy-paste developer experience.

## Why GlideCN?

Traditional page transitions in React often suffer from layout shifts, flashing unmounted content, or complex router locking hacks. GlideCN solves this through a synchronized dual-frame rendering architecture.

<Cards>
  <Card title="60 FPS Hardware Acceleration">

  </Card>

## 30-Second Quickstart

<Steps>
<Step>

### Wrap Root Layout

Wrap your root layout with `<GlideCNProvider>`:

```tsx title="app/layout.tsx"
import { GlideCNProvider } from '@/components/glidecn';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <GlideCNProvider defaultTransition="cube">
          {children}
        </GlideCNProvider>
      </body>
    </html>
  );
}
```

</Step>
<Step>

### Define Page Transitions

Wrap your page routes with `<Page>` and assign any transition:

```tsx title="app/contact/page.tsx"
import { Page } from '@/components/glidecn';

export default function ContactPage() {
  return (
    <Page transition="circular-portal" duration={0.7}>
      <main className="p-8">
        <h1>Contact Us</h1>
        <p>This page reveals with a circular iris portal.</p>
      </main>
    </Page>
  );
}
```

</Step>
</Steps>

## Architecture

GlideCN synchronizes with the Next.js navigation lifecycle to manage concurrent mounting of outgoing and incoming route segments.

1. **Global GlideCNProvider**: Intercepts navigations and orchestrates the timeline.
2. **Frozen Router Context**: Captures the outgoing route segment in a frozen visual boundary, preventing it from updating with new URL params or unmounting mid-animation.
3. **Pluggable Shader Registry**: Every transition is an isolated `TransitionDefinition` containing pure Framer Motion variants. You only bundle what you use.
